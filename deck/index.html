02 · Problem

An honest buyer and a liar get the same slow answer.

An order goes wrong. Someone reads the message, squints at a photo, opens the policy document, checks whether this buyer has done it before, and decides. Two to five days, and the outcome depends on who picked up the ticket.

Sellers lose twice

They refund claims they shouldn’t, and lose customers over claims they should have paid.

Buyers wait days

For an answer that was usually one policy clause away the whole time.

Fakes are now free

Generative tools make convincing damage photos in seconds. Manual review was never built for that.

Who this is for

  • Sellers on Shopify, WooCommerce and Instagram, and the platforms hosting them.
  • Buyers, who never see the machinery — only a faster answer with a reason attached.
  • Platforms, who need the cross-store fraud signal no single seller can see.
03 · Solution

Eight agents decide. Code moves the money.

Agents emit typed findings. A guarded tool layer enforces caps, evidence tiers, clause verification and idempotency. A fully compromised model still cannot issue a refund it is not entitled to — which is what makes autonomy safe enough to ship.

Live attested capture

The server issues a random, time-boxed instruction seconds before the camera opens. A photo prepared in advance cannot answer a question it had not yet been asked.

Evidence tiers

Attested live capture unlocks 100% of a store’s auto-approve cap, an unattested camera 50%, an arbitrary upload 25%. Friction proportional to risk.

Four ways a photo fails

Generator metadata and C2PA. No camera EXIF. The same image reused at another store. And the store’s own listing photo handed back as proof.

Version-aware policy

Judged against the pack in force on the purchase date, not today’s. Clause ids are verified against the real pack in code, so an invented clause fails closed.

04 · Architecture

Checkpointed graph, two human gates.

intake ──▶ capture ──▶ ┌ evidence ┐──▶ fraud ──▶ resolve ──▶ guardrail ─┬─▶ execute
             │         └ policy   ┘                                     │
      interrupt: camera        (parallel)                                ├─▶ seller_gate ──▶ execute
                                                                        └─▶ platform_gate ─▶ execute
                                                                              interrupt: human

Evidence and Policy run concurrently. Fraud waits for Evidence deliberately: scoring risk before knowing whether an image carries generator metadata throws away the strongest signal there is.

Orchestration

LangGraph 1.2.10, checkpointed. interrupt() freezes a case mid-graph for the camera or a human; the checkpoint survives a process restart, so a dispute resumes days later exactly where it paused.

Models

Claude Sonnet 4.5 for judgement and vision, Haiku 4.5 for volume work. Per-agent routing. A deterministic rule-based provider implements every agent’s decision function for tests and live-outage fallback.

Stack

FastAPI · SQLAlchemy · Postgres (SQLite in dev) · WebSocket event stream · Next.js 15 App Router · TypeScript · Tailwind · React Flow · Pillow for EXIF · Resend for mail

Data

Store, PolicyPack (versioned by effective_from), Buyer, Order, Dispute, Evidence, CaptureSession, AuditEntry, RefundLedger (unique on dispute_id), Precedent, Account, Session.

Integration contract

One script tag for the widget. Six required connector endpoints and four optional, HMAC-SHA256 signed over timestamp.body with a five-minute replay window. A merchant without courier pickup answers 501 and the engine degrades to posted return instructions rather than failing the dispute.

07 · Challenges & next

The bugs worth telling you about.

The Evidence Agent had never seen a photograph

It routed to a vision tier defaulting to a Gemini model name. Sent to the Anthropic endpoint that name is rejected, the call fell back to the rule-based provider, and the agent judged every case on metadata alone while reporting the image as verified. Model names are now validated against the active provider.

Missing data read as guilt

A buyer at an external store is not on our network. Reading that as zero orders and zero lifetime spend gave a nine-order customer a claim-to-lifetime ratio of 3450 and a fraud score of 0.92. A null is now a null — in the scoring code and in the prompt.

Decisions in the wrong name

When the watchdog hands a stalled case to the platform, the same graph interrupt is resumed by someone else. It was recording rulings in the seller’s name that they never saw.

Silent policy substitution

An unencoded as_of sent a raw + in a query string, which decodes to a space. The merchant could not parse it and would have judged the dispute under today’s policy instead of the one in force on the purchase date — wrongly, and invisibly.

Before the final round

  • Deploy to rezo.zevora.io with Postgres and a real queue
  • A Shopify app that installs the connector in one click
  • Serial-plate matching, so the unit photographed is provably the unit shipped
  • Voice intake for buyers who would rather talk than type
  • Load testing on concurrent disputes
08 · Impact

Thirteen hours a month, per seller.

India has millions of small online sellers handling returns by hand. At forty disputes a month and twenty minutes each, one of them gets thirteen hours back. The buyer gets an answer in a minute instead of three days.

Scalability

Stateless API in front of the graph. The checkpointer is the only stateful component and is already database-backed. Per-agent routing means volume work runs at Haiku prices.

Business model

Priced per resolved dispute, so a seller pays only when Rezo actually did the work. A platform tier for marketplaces that want the cross-store fraud signal.

Beyond e-commerce

The shape is not specific to retail: insurance claims, warranty service, rental damage deposits and field-service verification all have the same structure — a claim, evidence that can be faked, a policy document, and a decision that has to be explainable to the person it affects.

Every figure on these slides came from running the system, not from estimating it.
